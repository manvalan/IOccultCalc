█ ROOT CAUSES ANALYSIS
  ────────────────────

  Causa #1: Unità di misura (75% dell'errore)
    • OEF2.0 format: λ (mean longitude) in GRADI
    • Libreria: toKeplerian() attende λ in RADIANTI
    • Fix: Conversione λ_deg * π/180
    
  Causa #2: Frame mismatch (25% dell'errore)
    • File header: "refsys = ECLM J2000" (eclittica)
    • Dati reali: Già nel frame EQUATORIALE
    • Fix: Non applicare rotazione eclittico→ICRF

█ KEY INSIGHTS
  ────────────

  1. OEF2.0 Format Specification:
     → Mean longitude λ è sempre in GRADI
     → Conversione necessaria prima di passare alla libreria
     
  2. AstDyS Data Characteristics:
     → Header "ECLM J2000" è dichiarativo, non sempre accurato
     → Verificare sempre con confronto JPL Horizons
     → Alcuni asteroidi possono avere dati pre-rotati
     
  3. Frame Consistency:
     → Non assumere frame dalle intestazioni
     → Verificare con calcoli indipendenti
     → Sub-arcsecond accuracy rivela frame mismatches
     
  4. Testing Methodology:
     → Test incrementali per ogni fase di conversione
     → Documentazione da autorità (ITALOccultLibrary) essenziale
     → Comparazione con multiple sources (JPL, documento)
